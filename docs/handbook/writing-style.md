# 文风契约 v1（草案，待用户审）

**为什么要写**：2026-09-22 用户指出 `/typesafe-jev/resources` 读起来"太 AI"。复核后确认问题不是"暴露了抓取和核对"，
而是**写作视角错了**：句子主语是"我们/本页的做法"，而不是主题。人类编辑会把这些句子全删掉——**它们的密度就是那个 tell**。

**契约要防的**：页面变成"我们的工序报告"；以及反向错误——因为怕像 AI 而删掉出处、日期、边界，
把自己降级成第 9 个链接清单。**出处是结构，不是叙述。**

---

## 一、硬规则（可勾选）

1. **主语优先是主题。** 页面讲的是模型/资源/现象，不是我们的流程。
2. **"我们"只出现在两种位置**：
   a. 这条事实的来源确实是我们（我们的实测、我们的读数）；
   b. 我们给的是一个判断，而不是一条记录。
   —— 其他一切场合，删掉"我们"。
3. **出处进结构，不进叙述。** 页面级 = 一行 `Last checked <日期>`；条目级 = 来源链接本身。
   不在正文里解释"这个日期是干嘛用的"。
4. **方法在报告页占一节，在其他页占一行。**
5. **边界必须写，但写成一格，不写成一节。** 用陈述句（"No description published."），
   不用解释句（"我们因此选择只记录事实而不猜测"）。
6. **禁止的句式**（见到就删）：
   - "本页是……的索引 / 这个索引的索引"——自我介绍；
   - "我们在 X 日抓取了 Y，返回 200"——工序；
   - "为了让读者知道日期有多新，我们把日期印在 byline"——自解释；
   - "我们选择不写 X，因为 Y"——策略说明；
   - 同一件事说两遍（正文一段 + provenance 一行 + 脚注一句）。
7. **比例**：列表/索引页 **≥80% 的字讲主题**；单主题页允许"我们"变多，但必须因为我们就是内容来源。
8. **能示范就不宣称。** 不写"我们真读过代码"，写读过之后的结论。
9. **分组轴优先"读者要做什么"，其次"东西是谁的"。**（官方/社区可以留，但组名要是读者语言。）
10. **不写未来维护承诺**（"这一栏会变化、需要维护"→ 改成事实句："这八份清单里有五份是一周内出现的。"）。

## 二、允许的例外（不算违例）

- **报告页**（`/alpha-line-report`、`/typesafe-jev/statistics`）允许一整节 Method + "不能告诉你什么"：
  读者就是来看方法的，方法在那里是内容本身。
- **实测页**（`/typesafe-jev#our-run`）允许大量"我们"：那是我们作为唯一来源的事实。
- **提交/纠错入口**等操作性页面：说明流程是功能，不是叙述。
